# Smart Selection: расширенная техническая документация

Документ описывает фактическую реализацию Smart Selection и «Авто-длительности» в текущем коде проекта.

## Ответственность и точки входа

Smart Selection выбирает временные интервалы исходного видео. Повторное распознавание выбранных отрезков, субтитры, кадрирование, баннеры, кодирование и AI-метаданные выполняются следующими этапами.

Основная реализация находится в `app/processor.py`. Запуск задания и полное предварительное распознавание координирует `app/main.py`.

## Фактическая маршрутизация режимов

Значения `global`, `parts` и `hybrid` используют общий скоринг кандидатов, но разный порядок отбора: глобальный рейтинг, равномерные части и локальный топ-3 с финальным глобальным рейтингом соответственно.

~~~text
smart_mode == off
    -> последовательные интервалы по временной сетке

smart_mode in {global, parts, hybrid}
    -> полное распознавание
    -> duration > 7200 s ? нейросетевой путь : эвристический путь
    -> заполнение до запрошенного количества
~~~

Для видео длиннее 7200 секунд применяется `InterestNet` / `SegmentScorer`. Для обычных роликов используется эвристика по распознанным словам.

## Входные данные

Селектор получает:

- длительность исходного видео;
- слова с временными метками;
- требуемое количество роликов;
- фиксированную длительность либо диапазон Auto-duration;
- режим Smart Selection.

Полное видео сканируется `faster-whisper` моделью `base`. После выбора каждый отрезок распознаётся отдельно для более точных субтитров.

## Построение фраз

`_build_phrases` объединяет соседние слова, только если одновременно выполнены условия:

~~~text
gap < 1.0 s
phrase_duration <= 12.0 s
phrase_word_count < 40
~~~

Иначе текущая фраза закрывается и начинается новая. Ограничения устраняют случай, когда длинная непрерывная речь превращалась в одну многоминутную фразу и ухудшала генерацию кандидатов.

## Эвристический селектор фиксированной длительности

Алгоритм проходит по таймлайну окнами. Шаг кандидатов — примерно половина длины шортса:

~~~text
step = short_length // 2
candidate = [start, start + short_length]
~~~

В кандидат попадают фразы, пересекающиеся с его границами. Кандидаты оцениваются, сортируются по убыванию балла, затем выбираются лучшие непересекающиеся интервалы.

### Оценка окна

`_score_window_interest` использует:

| Признак | Максимальный вклад |
|---|---:|
| Плотность слов | 25 |
| Доля времени с речью | 25 |
| Средняя длина фразы | 15 |
| Доля уникальных слов | 15 |
| Эмоциональные маркеры | 10 |
| Темп речи | 10 |
| Бонус за число слов | до 2 |

Теоретический максимум равен 102, хотя оценку удобно воспринимать как шкалу около 0–100. Она нужна для относительного ранжирования, а не как пользовательский рейтинг качества.

Базовая эвристика напрямую не анализирует видеоряд, мимику, смены сцен и громкость.

## Непересечение и заполнение количества

После сортировки кандидат принимается, только если не пересекается с выбранными интервалами.

`_fill_requested_segments` затем пытается довести список до физически возможного количества:

~~~text
target = min(shorts_count, floor(source_duration / segment_length))
~~~

Он перебирает временную сетку и добавляет свободные непересекающиеся участки. Итог поэтому может содержать как окна с высокой оценкой, так и fallback-интервалы для выполнения запроса.

Это объясняет логи, где первые сегменты идут подряд, а следующие начинаются позже. Это не переключение на отдельный `hybrid`, а заполнение внутри общего алгоритма.

Если запрос превышает физический предел, возвращается максимально возможное количество.

## «Авто-длительность»

Входной диапазон нормализуется:

~~~text
min_length = max(15, requested_min)
max_length = max(min_length, requested_max)
~~~

Алгоритм работает в две фазы.

### 1. Базовые сегменты

Сначала выбираются непересекающиеся окна длиной `max_length`. Вместимость исходника также считается по максимальной длине. Это консервативно предотвращает пересечения после уточнения границ.

### 2. Уточнение

`_refine_segment_duration` перебирает допустимые варианты начала и длины. Длительности проверяются с шагом 5 секунд, а каждый вариант оценивает `_score_window_interest`.

~~~text
best = base_window

for length from min_length to max_length step 5 s:
    for allowed_start in candidate_starts:
        score = score_window(allowed_start, allowed_start + length)
        if score > best.score:
            best = current_window

return best
~~~

В результате ролики одного задания могут иметь разную длину, но остаются в заданном диапазоне.

Особенности:

- минимум принудительно ограничен 15 секундами;
- максимум не может быть меньше минимума;
- шаг 5 секунд балансирует качество и стоимость перебора;
- оценка опирается на структуру речи, а не гарантированную завершённость мысли;
- вместимость считается по максимуму диапазона, поэтому результат может быть меньше теоретического числа роликов минимальной длины.

## Путь для видео длиннее двух часов

При длительности свыше 7200 секунд вызывается `_find_best_segments_nn` с `InterestNet` и `SegmentScorer`.

Он формирует расширенный набор признаков сегмента и ранжирует кандидатов моделью. При доступном OpenAI API возможно дополнительное LLM-переранжирование. Если ключ или внешний сервис недоступен, локальная оценка остаётся основным рабочим вариантом.

## Последующий пайплайн

После выбора `[start, end]`:

1. FFmpeg извлекает участок.
2. Отрезок распознаётся для субтитров.
3. Видео приводится к 1080×1920.
4. Добавляются субтитры и баннер.
5. Аудио кодируется в AAC, видео — через NVENC или CPU fallback.
6. После рендера могут генерироваться заголовок, описание и хэштеги.

### Баннер с паузой

Пауза не увеличивает выбранную длительность. Интервал источника длиной `D` заменяется вставкой той же длины:

~~~text
source_before + banner_D + source_after_until(original_duration - D)
~~~

Аудио баннера вставляется последовательно через `concat`, без смешивания с основной речью. Для изображения или видео без аудио используется `anullsrc`. Обычный overlay не добавляет звук баннера.

## Производительность

Главные затраты времени — полное распознавание, повторное распознавание выбранных сегментов и FFmpeg-рендер. Эвристический скоринг значительно дешевле. Параллельные workers ускоряют обработку уже выбранных сегментов, но не меняют результат выбора.

## Диагностика

~~~text
Scanning full video (base model) for smart selection...
Scan done: <N> words
Found <N> segments
Processing <N> segments in parallel (<W> workers)...
[i/N] Processing <start>s-<end>s
[i/N] Video created
~~~

Если `Found N segments` содержит нужное число, но готовых файлов меньше, проблема находится после селектора: в распознавании конкретного отрезка, FFmpeg, записи файла или параллельном задании.

## Регрессионные проверки

1. Исходник 964,7 секунды, длина 59 секунд, запрос 10 — возвращаются 10 непересекающихся интервалов.
2. Для короткого исходника число не превышает `floor(duration / length)`.
3. При непрерывной речи фраза не превышает 12 секунд или 40 слов.
4. В Auto-duration каждая длина входит в заданный диапазон.
5. Интервалы не пересекаются и не выходят за длительность исходника.
6. `global`, `parts` и `hybrid` дают различающиеся результаты на одном наборе кандидатов.

## Известные ограничения

- Режим `parts` ставит равномерное покрытие выше абсолютного глобального рейтинга.
- Эвристика ориентирована на речь и не оценивает визуальную динамику.
- Auto-duration не гарантирует границу законченного предложения.
- Fallback гарантирует количество, но может выбрать менее содержательный фрагмент.
- Отдельные стратегии распределения по частям и настоящий гибрид нужно реализовать до их позиционирования как разных возможностей.
